우렁의사 AI 챗봇 설계 문서

이 챗봇이 왜 다른지, 어떤 명령을 넣었는지, 무엇이 아직 부족한지

2026년 8월 · 대화 모델 gpt-4o · 기억 정리 모델 gpt-4o · 최근 대화 30턴을 프롬프트에 주입

한 줄 요약 — 일반 상담 AI는 “들어주고 공감”에서 멈춥니다. 우렁의사는 왜곡인지 현실인지 먼저 가르고, 현실이면 생각이 아니라 상황을 바꾸라고 말합니다. 그리고 그 판단을 사람마다 누적된 사례 기록 위에서 내립니다.

Ⅰ다른 AI와 무엇이 다른가

ChatGPT에 “상담해줘”라고 하는 것과의 실제 차이

항목일반 AI · 보통의 상담 챗봇우렁의사
판단공감·타당화에 수렴. 의견을 잘 안 냄의견 표명 트리거가 명시됨 — 착취·반복 손해·자기파괴 신호에선 반드시 입장을 밝힘
인지왜곡부정적 생각 = 왜곡으로 간주하고 교정 시도근거 유무를 먼저 가름. 근거가 있으면 왜곡이 아니라 관찰 → 상황 변경(경계·거리두기)으로
기억세션 단위. 대화창 닫으면 소실매 대화 후 사례 기록을 비동기 갱신. 이름·관계·반복 주제·효과적이던 접근·둘만의 농담까지 축적
사례 개념화없음핵심신념 → 두려움 → 행동 → 결과 가설을 세우고 다듬고, 때가 되면 말로 꺼냄
기법일반론적 조언CBT·DBT·MBCT를 상태에 따라 선택. 감정 강도 6~7 이상이면 통찰 탐색을 멈추고 고통감내 우선
출력 형태긴 문단 하나메신저처럼 짧은 말풍선 여러 개(||| 분할) + 감정 스티커
앱 연동없음앱 전 기능을 학습. 위치 안내 + [이동:탭]으로 실제 화면 이동, 대화에서 사고기록 자동 생성
안전일반적 안내위기 신호 시 유머·기법 중단, 안전과 연결에만 집중 + 1393·1577-0199 자동 노출

실제로 이렇게 갈립니다 — “날 이용하는 사람 아닐까?” + 최근 세 번 다 내가 냄

기존 “그런 생각이 들면 진짜 힘들겠다.”
→ 감정만 받고 사안은 안 건드림. 벽에 대고 말하는 느낌.

현재 “세 번 다 네가 냈으면 그건 기분 탓이 아니야.”
→ 관찰로 인정하고, 재구성이 아니라 경계 설정으로 넘어감.

Ⅱ어떤 명령을 넣었는가 — 프롬프트 7층 구조

파일: js/llm.js 의 CORE_PROMPT

1
사람처럼 대화하는 법 가장 중요11개 원칙. 말투 미러링, 매번 질문으로 끝내지 않기, 같은 질문 반복 금지, 상투적 회피어 금지(“언제든 얘기해”, “도움이 됐으면 좋겠어” 등 명시적 금지 목록), 감정만 받고 내용은 안 건드리는 답장 금지, 같은 고민이 2회 이상 돌아오면 관점 제시 의무.
2
세 가지 치료의 통합CBT(생각 재구성)·DBT(수용과 변화, TIPP·DEAR MAN·FAST)·MBCT(탈중심화·3분 호흡). 기법 이름을 사용자에게 나열하지 말고 대화에 녹이도록 지시.
3
왜곡인가, 진짜인가 이 앱의 핵심재구성 전에 반드시 분기. 근거 없음 → 인지 재구성 / 근거 있음 → 완화 금지, “네가 본 게 맞을 수 있어” 인정 후 상황 변경 / 애매함 → 함께 증거 수집. “착취·학대 앞에서 마음챙김을 권하는 것은 오답”이라고 못 박음. 의견 표명 형식도 규정: 관찰 → 내 생각 → 근거 → 결정권은 너에게.
4
사람 먼저 읽기감정 강도·필요한 것(진정/통찰/수용)·왜곡 유무·충동 위험을 매 순간 가늠. “들어주기가 먼저지만 먼저는 영원히가 아니다” — 진정되면 본론 복귀 의무.
5
안전 최우선 P1자·타해 신호 시 응답에 위험감지를 포함 → 시스템이 1393·1577-0199 안내를 띄움. 위기엔 유머·기법 설명 중단.
6
세션의 시작과 마무리오래 비웠다 오면 새 세션으로 반갑게 인사하고 지난 이야기 후속을 물음. 마무리 신호 감지 시 [세션끝] 표식 → 시스템이 세션을 정리하고 사고 기록을 자동 생성. 먼저 대화를 끊지 않음.
7
장기기억과 사례 개념화“기록을 보니…”라고 말하지 말고 아는 사람이 기억하듯 쓰라고 지시. 개념화 구조를 명시: 핵심 신념 → 두려워하는 것 → 하는 행동 → 그 결과. 가설이 서면 때를 봐서 말로 꺼내되, 사람을 규정하는 무기로 쓰지 말고 “맞아?”라고 함께 확인.

여기에 실행 시점마다 덧붙는 것들

  • 페르소나 지침 — 선택된 상담사(햇님/달님/소나무)의 말투·전문 기법 블록
  • 앱 사용 가이드 — 전 기능 위치·게임 경제·가격까지. 기능이 바뀌면 이 가이드도 함께 갱신
  • 현재 시각 — “한낮에 잘 자라고 하면 즉시 AI 티가 난다”며 시간대 엇박자 금지
  • 다가오는 명절·기념일, 사용자 이름, 언어 모드(한/영/일)
  • 음성 모드 지침 — 보이스톡 중에는 문장을 더 짧게
  • 장기기억 본문 + 세션 안내

Ⅲ상담사 4인 — 기법을 인격으로 나눴다

같은 기억을 공유하되 접근이 다름 (파일: js/personas.js)

상담사기법이럴 때수업 코스
🐌 우렁의사통합일상 대화·처음 시작—
☀️ 햇님CBT“다 내 잘못이야” 생각이 안 떠날 때햇살 수업 6단계
🌙 달님DBT감정을 그냥 쏟아내고 싶을 때달빛 수업 6단계
🌲 소나무MBCT같은 생각을 곱씹어 잠이 안 올 때솔숲 수업 6단계

수업은 한 턴에 한 단계씩 진행하고, 답장 첫 줄에 ☀️ [2/6] 자동적 사고처럼 진행 상황을 표시하도록 지시했습니다. 중간에 힘들어하면 멈추고 감정을 돌본 뒤 이어갑니다. 달님은 코스 중에도 존댓말과 수용적 태도를 유지합니다.

자동으로 도는 것들 사용자 개입 없음

  • 장기기억 갱신 — 매 대화 후 비동기. 기본정보·관계·반복 주제·인지 패턴·사례 개념화 가설·현실 문제(왜곡 아님)·효과적이던 접근·다음에 물어볼 것을 500단어로 압축
  • 사고기록 자동 생성 — 세션 종료 시, 또는 사용자 발화가 8개 쌓이면 조용히 추출 (잡담이면 자체 판단으로 걸러냄)
  • 맞춤 숙제 — 최근 대화를 읽고 오늘 30분 안에 할 수 있는 행동 과제를 처방
  • 주간 편지·우편함 답장 — 우렁이 말투(우로로록·우덩우덩)로 작성

Ⅴ왜 이게 좋은가

  • “착한 말만 하는 AI”의 함정을 구조로 막았다. 회피어 금지 목록과 의견 표명 트리거가 프롬프트에 명시돼 있어, 모델이 안전한 공감으로 도망가기 어렵습니다.
  • 가스라이팅 방지. 근거 있는 지각을 왜곡으로 취급해 “생각을 바꿔보자”고 하는 것이 가장 위험한 실수라고 프롬프트에 못 박았습니다.
  • 관계가 누적된다. 사례 개념화가 기억에 남아, 3주 뒤에도 “이거 저번 A랑 같은 모양 아니야?”가 가능합니다.
  • 앱과 한 몸이다. 대화가 사고기록·감정 데이터로 바뀌고, 그게 다시 리포트의 근거가 됩니다.
  • 기법이 인격으로 분리돼 진입 장벽이 낮다. “CBT 받으세요” 대신 “햇님한테 가봐”가 됩니다.

Ⅵ개선해야 할 점

솔직하게 — 지금 알고 있는 약점

우선순위 높음 P1

  • 안전 감지가 모델 자기신고에 의존한다. 위험감지를 모델이 안 쓰면 배너가 안 뜹니다. 자·타해 표현에 대한 규칙 기반 이중 안전망(키워드+맥락 필터)이 없습니다. 임상 앱에서 가장 시급한 구멍입니다.
  • 의견 표명의 과교정 위험. “겁내지 말고 말하라”를 강화한 만큼, 근거가 얇은데 단정하는 실패가 생길 수 있습니다. 지금은 모델 자율에만 맡겨져 있어, 확신도에 따라 표현 수위를 조절하는 규칙이 필요합니다.
  • 사례 개념화 검증 절차 부재. 가설이 틀렸을 때 스스로 폐기하라고 적어뒀을 뿐, 반증 이력을 남기는 구조가 없습니다. 틀린 가설이 기억에 남아 계속 재생산될 수 있습니다.

우선순위 중간 P2

  • 기억이 500단어 요약이라 손실이 크다. 압축 과정에서 중요한 디테일이 사라집니다. 사건 단위 인덱스 + 필요할 때 꺼내 쓰는 검색형 기억이 더 낫습니다.
  • 프롬프트가 매우 길다. 7개 섹션 + 페르소나 + 앱 가이드 + 상황 블록이 매번 들어가 토큰 비용과 지연이 큽니다. 상황별로 필요한 블록만 넣는 조립 최적화가 필요합니다.
  • 수업 코스 이탈 처리가 약하다. 6단계 중간에 다른 얘기로 새면 코스 상태가 흐지부지됩니다. 진행 상태를 앱이 들고 있지 않고 모델 기억에만 있습니다.
  • 말투 미러링과 달님의 존댓말 고정이 충돌할 수 있습니다. 우선순위는 명시했지만 실제 검증은 안 됐습니다.
  • 효과 측정이 없다. 어떤 개입이 실제로 기분 점수를 올렸는지 추적하지 않습니다. PHQ-9 재측정과 개입 이력을 연결하면 근거 기반으로 개선할 수 있습니다.

우선순위 낮음 P3

  • 다국어(영·일) 모드에서 페르소나 말투 품질이 한국어만큼 다듬어지지 않았습니다.
  • 스티커 40여 종 중 실제로 자주 쓰이는 건 소수 — 사용 빈도 기반 정리가 필요합니다.
  • 앱 가이드가 프롬프트에 하드코딩돼 있어, 기능 변경 시 수동 동기화가 필요합니다.
